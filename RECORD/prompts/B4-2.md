# B4-2 — unlock the storefront on checkout (grammar-served agent)

Stage: B4, addendum (`beta-B4-r3`). Recorded 2026-10-17 before running, verbatim from Frank,
with the Shopify assistant's instruction he pasted. On top of `beta-B4-r2`.

```
okay, this is working great; I'd like to keep testing locally, which is currently running on localhost:8082, I want to remove the need for the password. so that  the site checkout goes straight to shopify checkout form
```

```
shopify says we can add the password via a post request,
POST https://asteroid-metals.myshopify.com/password
Content-Type: application/x-www-form-urlencoded

form_type=storefront_password
&utf8=✓
&password=<storefront password>
```

Read as: on "Proceed to checkout", the app unlocks the storefront with that POST and then opens
Shopify's checkout, so the visitor never sees the password page. Browser constraint: the unlock
cookie is first-party to the Shopify origin, so the POST is a top-level form submission into a
new window on that origin (a cross-site fetch could not set it), and that window is then sent to
`checkoutUrl`. The password value is never written by the agent: Frank's tool
(`RECORD/tools/shopify-config.mjs`) copies it from his environment into `config.shopify`, and
from there it ships in the public bundle — accepted by Frank for a development store with a
test-only gateway.
